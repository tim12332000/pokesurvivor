## 2. 全局遊戲提案

### 核心承諾

玩家透過走位安排敵群位置，再以有意義的選卡改變角色自動出手條件。維持一個移動搖桿即可遊玩的底線；本階段不新增四個手動技能按鍵，不讓演出要求迫使整個操作系統重做。

一輪核心循環：**觀察敵種與進攻方向 → 走位排列威脅／回收經驗 → 三選一確立出手偏好 → 用偏好處理下一種敵人 → 首領驗證流派弱點 → 提供補短板的選擇而非固定加傷。**

角色數值面與演出面應共用這個循環。鏡頭保持玩家在可辨識區，傷害範圍不靠滿屏大光圈表現；真正重要的是「這次下一招打哪裡、何時命中、哪裡仍危險」。

### 成長節奏（以下為待測試假說）

1. 前兩次實際選卡內，玩家應見到一次能辨識角色特色的選擇；不是只抽到攻擊／磁鐵。
2. 第三～第五次實際選卡開放一個角色路線分歧，佔用當次卡位，允許拒選；不要硬把同一效果分別套在所有人的Lv.3／6／9。
3. 首個180秒首領前，正常經驗路線應有一個可讀的核心技能組合，但不是保證已學全套。具體到達等級先以固定種子、當前全滿永久強化政策實玩決定；若需零perks比較，另建並明示隔離測試模式。清空存檔或使用未購買帳號都不會繞過當前強化政策。
4. 五階技能不再四次全是相同百分比傷害；至少一個階段改善行為，且在圖鑑明列代價。其他階段仍可用小幅數值改善，避免每次選卡都要重學規則。
5. 20級試玩提供「白板技能／已選卡路線」兩個明確模式。白板模式標明四招一階；路線模式須用與正常局相同的19次選卡預算產生，不直接免費滿技。

### 卡牌與流派契約

- 學招、升階、全局屬性共用選卡機會；新增分歧也用這個預算。
- 每個角色路線至多一個不可同時取得的分歧選擇，避免記憶六七層條件。
- 數量、範圍、CD的每一類都要在技能說明中有明確有效對象。無有效對象的數量牌不進該角色候選池；不要顯示可選卻完全無收益的卡。
- 數量改變「可覆蓋目標」而不直接多倍打同一目標，適合清群；傷害／暴擊偏對單體；CD要顯示受動作時間限制的有效節奏，不承諾單純百分比DPS。
- 不沿用基礎引擎的融合UI來假裝JJK有融合流：目前JJK是零主動槽，自然不能用原來的主動槽融合取捨。若要跨角色共用融合，應另做全角色系統方案，不能在本輪偷偷補一個特例。
- 共通「分身之術」不是火影角色限定：`js/systems/self-clone.js:5`、`:46`～`:65`、`:362` 會產生獨立受控戰鬥演員，生命／攻擊為來源約三分之一並沿用招式。因而「一個owner最多一隻里香」不等於整場只會有一隻。鏡像角色的里香須有較弱輪廓／明確owner標記；全畫面裝飾預算要涵蓋分身，不能只測單一主角。
- 吸血、生命剝奪、傷害擴散會改變行為選擇的收益。`lifesteal.js`依歸屬傷害回血，`percent-health-damage.js`依每次原生命中附加最大HP成分；`damage-splash.js`文字說單體，而三個JJK模組的範圍命中也逐一呼叫它。這須先決定全局AOE／二次傷害政策，再談「碎面清群流」，不能在設計中忽略或把每段動畫都當額外命中。

## 4. 敵人、首領與失敗體驗

- 保留現有敵人為內容基礎，不另建咒靈素材大工程。用現有追擊／遠程／盾／支援組合測路線，外觀世界觀混搭先承認是跨界遊戲。
- 第一次教學遭遇只要求觀察一種危險；第二段加入側面圍攻，讓石流不能只原地打直線；第三段加入少量可辨遠程敵人，讓烏鷺反制有出場理由。
- 不能讓烏鷺的路線在很長一段沒有可反射敵彈時完全失效：反制路線仍保有基本碎面，但優勢要在射手組合才顯現。
- 首領避免僅靠血量拉長時間。用「正面耐受／移位／短召喚」等已存在能力組合，驗證穿線、接力、反射的優缺點；新增首領機制屬下一工作項，未實作前不寫完成。
- 失敗頁要能回答：死於接觸／飛彈／地面危險哪一類；本局主要傷害與所選路線是什麼。不要只給總殺敵與最大等級，否則玩家無法修正選卡。
- 對首次失敗，提供重試相同種子與相同角色的入口，作為學習用選項；不是死亡後免費保留所有戰鬥強化。

## 6. 美術與程式特效的邊界

| 必須用可靠角色原畫／動畫表現 | 適合演算法產生的部分 | 共同必須滿足 |
| --- | --- | --- |
| 臉、髮型、毛領／耳飾、手部抓面、額頭蓄力姿態、里香甲殼與下顎；受傷／倒下完整身份 | 砲線外殼／尾跡、壓縮波、刀刃掃過的短殘影、折面紋理位移、有限碎片／命中火花、反射軌跡 | 同一來源點、同一模擬時鐘、同一接觸事件；程序層不改命中邏輯。 |

不是每個效果都要畫成大PNG。烏鷺的背景扭曲可用程式把小範圍背景裁片映射成摺面；角色抓取的手和肩膀仍需要原畫，不能整個人用Canvas扭曲代替動作。低階手機可退化成少量有明暗面的折片，但保留攻擊邊界與時刻。

### 單一動作事件契約（提案）

```text
castId + owner + moveId + variant
sourceWorld / aim / lockedTargetWorld
windupStart / contactTimes[] / recoveryEnd   // simulation clock
collisionShape + reach + radius + occlusionPolicy
actorLayer + emitterAnchor + readabilityClass
```

傷害系統擁有 `contactTimes` 及已命中集合；動畫和程序特效訂閱同一事件。畫面不能自己用 `performance.now()` 推一個不同接觸時刻。暫停、死亡、換局與角色移除使整個cast失效，沒有殘留尾光觸發新傷害。

乙骨接力標記、石流鎖線與烏鷺反射的每個新提案都要先加對應事件資料，不能以圖上亮點暗示不存在的遊戲狀態。

## 7. 可讀性規格與驗收

1. 手機390×844下，玩家頭／胸／雙腳仍能辨識；里香或碎面不能覆蓋玩家輪廓。背景中的敵人危險預告優先於己方裝飾。
2. 同場三名以上精英時，強調一個當前目標；普通怪不每個都疊滿標記、浮字、外光。
3. 裝飾層的碎片／光束毛邊不得暗示超出實際半徑的可命中區。範圍輪廓可低透明持續，強閃只在接觸一瞬。
4. 最低畫質保留來源點、主要方向與接觸時間三項，先關閉裝飾分片／二次波紋；不能用關閉全部特效來達到效能數字。
5. 每條路線用同一種子、同一19次選卡預算、當前全滿永久強化政策對照：記錄時間、殺敵、首領剩餘血、承傷來源、技能實際施放間隔及選卡耗時。若未來增加零perks模式，須獨立標籤並重跑全套，不混算。數量／CD／範圍卡至少各測零／一／上限。
6. 玩家測試問題：不讀說明能否指出額砲來源、目前誰在攻擊、天空幕還能擋幾次，以及為何這條路線要靠近或遠離敵人。這些比自給美術分數更能判斷設計是否成立。
7. 驗收分成原作相符、玩法機制、動作命中、可讀性、效能五欄；任一欄缺證據不能用其他欄的通過代替。

## 8. 推進次序與拒絕方案

先做卡牌實際收益／試玩標籤審計 → 單一角色兩路線可玩草案 → 配套演算法特效小原型 → 同種子預算對照 → 再擴到三人。這個順序不等於縮小最後三人範圍，而是減少把錯誤模板複製三次的風險。

拒絕：先追加更多招式、加滿屏光效、免費提高所有技能傷害，再補企劃理由。原因是這些不能修正選卡無效、行為同質與壓力設計不清楚。

拒絕：為了動漫忠實直接照搬全部時間限制／領域。原因是生存遊戲節奏不同，且目前官方材料不足以支持所有細節；應保留招式語意，讓改編數值接受遊玩驗證。

待第二階段和三位同儕討論的分歧：保留全自動是否能靠路線條件提供足夠決策；反射路線在當前射手密度是否可用；數量牌應精確落地還是先對無效角色禁選；程式化背景折射的最低可讀成本。
