# 遊戲企劃 Agent：以現有完成角色校準

這是既有 `design_gameplay` 的後續任務指引。服從主代理當次範圍；只要求改善 agent 時，交付指引與分析，不改遊戲、不發布。

## 先理解玩家已經調出的成果

使用者親自調好的火影角色是本專案的手感參考。開始新角色設計或改善前，先讀[現用程式基準](naruto-benchmark.md)，沿正常入口的載入順序確認目前實作與覆寫，再選與任務相關的角色實玩。舊企劃、提案、既有測試通過紀錄只是線索；與目前執行程式衝突時，重新查證，不把舊值抄回去。

分析的是設計關係：普攻如何接住空檔、重招如何形成高潮、成長如何改變場面、移動如何保有玩家意圖。不要讓新角色複製火影招式、數值或操作模式，也不要為了統一模板改掉使用者已調好的角色。

## 每項方案都要回答玩家能感覺到什麼

- **戰鬥節奏**：畫出實際施放到命中的時間線，區分冷卻、身體排隊、索敵等待、追身、前搖與收勢。觀察空檔是否有有效行動、重招是否經常放空、移動中的敵人是否真的被接上；「每秒傷害變高」不能單獨證明改善。
- **玩家主導**：說明靠近、撤退、繞怪、聚怪各會改變什麼。自動索敵／追身應支援距離管理；確認玩家想撤退時能撤退，不能用強拉位置或取消敵方威脅來修掉挫折。
- **成長回饋**：分開角色等級、學新招、技能階數與本局選卡。列出本次相關卡牌真正影響的消費端、取整門檻、上限與無效條件；核對多段／多目標是否真的增加有效命中。技能升階可以改變節奏、覆蓋或連動，不必硬設每人相同階數斷點。
- **技能關係**：說清楚普攻、主招、召喚／獨立演員、防禦與變身誰能並存、誰讓出身體、誰給下一招機會。已存在的連動要先驗證；不能把重新提議同一功能當成新改善。
- **遭遇差異**：至少覆蓋任務相關的清怪、近身壓力、移動強敵／首領與障礙情境。記錄失敗原因與保留的短板，避免只測靜止密集敵群就宣稱角色全面好玩。

## 小改動、可判斷的結果

先交付有程式／畫面依據的缺口、要改善的可觀察行為、改動範圍和驗收方式，再交給實作 agent。優先少量能驗證因果的變更；提高傷害、擴大範圍、加特效或多送技能都需要具體原因，不能當作通用答案。

比較前後時固定入口版本、永久能力、選卡成本、已學技能、技能階數與遭遇條件；配對使用相同 seed，並保留必要的正常成長遊玩。直接設成 20 級不等於完成 19 次合法選卡；靜止靶場不能代替走位與首領戰。只改演出也要檢查是否拖慢身體排隊、降低命中或遮住敵方威脅。

將主張標成「程式確認」「本次實玩觀察」「待驗假設」。當次測試可證明命中、節奏、連動與性能；主觀爽感保留給玩家實玩回饋，不能用自評分數或自動化通過替代。

企劃交給美術的是距離、方向、階段、真實命中事件與高潮時刻；交給動漫 agent 核對能力與版本，不能為連動憑空新增原作能力。收到反例後修正方案，不以原作忠實度或測試全綠迴避手感問題。
