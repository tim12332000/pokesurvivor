## 2. 完整玩法方向：先建立可選的戰術，再加更亮的效果

核心維持「移動找輸出角度→擊殺→冒險回收經驗→三選一卡→改變下一段走位與攻擊方式」。不建議本次突然強迫所有JJK改成手動瞄準＋多按鍵：原作能力不等於操作映射，現有手機搖桿與自動索敵需要延續。也不因基礎引擎有Q/E，就假設JJK必須塞滿主動槽。

真正要新增的是**互斥變體造成可理解的機會成本**，而不是四招全拿後只挑純增傷。第一個角色變體應在第一個180秒首領之前出現，暫定Lv6；第二輪里程碑先做形態深化，不再加一層通用資源條。Lv6只是起始假設，要用自然成長的多種子實測時間核對，不能照搬現有數字當作企劃理由。

同角色變體互斥，卡片顯示強化與代價；不是兩張都抽到後抵銷弱點。優先掛到現有招式定義／run內玩家狀態，不新建角色副本或替換存檔ID。先只支援一個變體選擇；整套雙分支完成測試後才考慮更複雜融合。

### 卡牌契約應先於變體實作

1. **數量卡一致性**：石流改用 `min(cap,G.Quantity.count(owner,baseCount))`，而非另發明線性3+Q。全owner能力都達count上限時應停止出現無效數量卡。乙骨／烏鷺沒有可增數的本體能力時，不應因人物標籤而送出無效卡；但若已學自身分身等可增數機制，仍可出現。不要為了讓每張卡都有用而增殖多隻里香或硬把數量轉成面積。
2. **冷卻卡**：保留0.92累乘，但身體動作排程與前搖不被無限壓縮。HUD應顯示已就緒但等前招收勢，避免玩家誤以為倒數0卻失效；比較實際施放間距，不能只比較m.cd。
3. **擴散傷害**：需明確決議維持「每鄰居獨立10%」還是改成「每次primary命中產生一筆10%總預算，分配鄰居」。我建議後者並改文案，讓範圍技不以N個primary互相擴散而近似N²增長。這是平衡改動，必須另作舊／新同種子對照，不能當作修字偷偷改掉。
4. **百分比生命附傷／吸血**：只由真實傷害事件處理，不讓刀光、爪痕、網格碎片重新呼叫hurt。單次攻擊多段特效不等於多次on-hit；想加真實連擊時需在企劃表列primary次數與總傷害。
5. **範圍**：現有JJK升階主要是傷害，沒有證據可直接說通用範圍卡已存在。若要新加，應明確分開搜尋距離、命中長／寬、控制半徑、特效外框；不能一個range變數混用。

### 敵人、首領與整局節奏

保留現有180秒一輪的首領時鐘作第一版比較基準，不先調成「更多怪」掩蓋角色分工問題。前三分鐘至少出現可被區分的少量威脅：追近身怪、側繞怪、可讀彈道遠程怪。讓站位改變輸出效益：長排利石流，壓近身逼乙骨選進退，遠程混編讓烏鷺反射有價值。支援怪仍遵守原生每種最多3隻的限制。

第一首領檢驗完整基本循環；第二／三首領增加移位與側向壓迫，避免單純血量成長讓聚束唯一最佳。900秒後先提供成績節點與繼續無盡選項，不因這次角色設計直接刪掉原本的長局玩法。死亡回顧顯示直接傷害、二次傷害、受到的主要威脅、已選變體與實際施放數，幫玩家理解下局怎麼改；不只列最大傷害。

## 3. 技術提案一：有界噪聲光束＋保守碰撞

### 已運行的CODE

- `algorithms.js`：`rayBox`、`clippedBeam`、`beamHit`、`beamProfile`。
- `prototype.js:drawBeam`：三層光束，不使用shadowBlur。
- 原型頁「01青白額砲」。靶的綠／棕狀態由碰撞結果決定，牆後靶不受傷；拖動時間到0.64與0.66可比較接觸事件。

資料：`BeamCast{owner,castId,run,origin,aim,range,radius,contactAt,hitIds}`；視覺資料只加 `profilePoints,seed,age,life`。寬度函數為 `radius × taper(u) × boundedNoise(u,seed)`，且任何噪聲結果都不超出physical radius。種子與輪廓在施放時生成，時間只改透明度／包絡，避免每幀抽亂數抖動。

碰撞先把障礙AABB向外擴張radius，再用slab求最早入射距離；這是保守近似，角落可能提早截斷，但不穿牆。正式地形是原生World查詢，第一步可保留既有取樣；若替換成格網DDA／碰撞AABB清單，必須與原生prop blocker對照，不可把原型的矩形牆函式直接當作全遊戲地形實作。

```js
const physical=clippedBeam(feetOrigin,aim,range,radius,nearbyWalls);
if(clock.crosses(contactAt))damageOnce(physical,castId);
const head=art.pointFor(owner,releasePose,'muzzle');
drawProfile(projectGroundToHead(physical,head),cachedProfile,visualAge);
```

**接入契約**：`jjk-ryu.js:122–168` 只產生一次release packet；`pointFor`提供圖格錨點；範圍卡與倍化後須重新核對foot→head投影與近場stub。擊中線的近端與遠端都需測量，不能只驗證「beam起點等於同一個helper回傳值」。前搖細線、釋放白核、後座殘光分開，不將殘光當作還能傷害。

**成本預算假設**：桌機每砲48點、手機20點；每名owner最多2條主砲輪廓＋散射9道的簡化輪廓，裝飾budget32不影響傷害；亮核最多兩筆stroke。測試需包括64敵、2自身分身、數量上限，不能只測一條空場光束。

## 4. 技術提案二：真的背景折面，而非在地上畫幾條線

### 已運行的CODE

- `algorithms.js`：`skyMesh`共享頂點、`affineTriangle`解六參數仿射映射、`drawTriangle`裁切貼圖、`reflect`反射向量。
- 原型頁「02天空折面」確實彎曲棋格與柱狀背景；前景替身仍維持原座標。這只是提案原型，不是正式烏鷺已做背景折射。

每個矩形網格共享相同vertex array，三角片只存三個索引。源頂點s、目標頂點d由折面位移函式生成，以 `M × [sx,sy,1] = [dx,dy]` 解出Canvas2D `a,b,c,d,e,f`。依目的三角clip，再transform並drawImage同一張背景快照。邊界位移為0，避免整塊世界漂走；內部摺線用共享頂點連續變形。

```js
const snapshot=captureBackgroundRegionBeforeActors(region); // 每cast一次、可重用RT
const mesh=deformSharedVertices(rect,foldProgress);
for(const triangle of mesh.indices)
  drawTexturedTriangle(snapshot,triangle.source,triangle.destination);
```

**正確接入位置**：在 `js/game.js:780–783` 地面／液體後、actors之前取得區域背景；只保存局部快照，禁止把玩家、彈道、HUD一起折射。`Camera`與DPR先在明確的world→screen矩陣轉換，snapshot使用screen pixels；歸還world draw時做逆轉。不要用整張主canvas在AirFields反覆自我複製造成回授與多重扭影。

反射本身沿 `v' = v − 2(v·n)n`，每片折面的normal由兩端世界點求出；但若企劃決定幕仍為360度圓形保護，就用圓接觸點法線／多片面連成圈，不能畫單面盾卻全周擋彈。高速彈用上幀位置→本幀位置求第一次接觸，保留現有 `.omx/jjk-uro.js:98–123` 的swept判斷。計算visual reflection normal前，先確定這是希望改變的遊戲行為；目前是原速度反向，不能悄悄改。

**成本與降階**：桌機6×4格48片、手機3×2格12片；同owner同時最多1片snapshot，建議最大512×512實像素。低階模式只保留12片與一條主折線；極低階回退既有canvas色面，碰撞和反射結果完全相同。截圖一次的背景會短暫凍住，所以持續時間先限制0.45秒；若要2.3秒幕維持動態折射，應每隔3幀更新快照並實測，不能把一次貼圖成本推論為持續動態成本。

## 5. 技術提案三：弧長一致的刀刃／爪痕拖尾

### 已運行的CODE

- `algorithms.js`：三次Bezier、96步弧長LUT、等距重取樣、依相鄰切線法線生成ribbon。
- 原型頁「03刀刃軌跡」可暫停拖時間；0.42秒才觸發一次hit，帶狀拖尾隨頭部進度走，不是整個扇形同時亮起。

Bezier參數t並非等速，直接每幀t+=dt會在部分段落忽快忽慢。先建立累積距離LUT，再以目標弧長反查t，得到等距點。刀痕兩側為 `p ± normalize(perpendicular(tangent)) × width(age)`。同樣的方式可做里香三條爪痕，各曲線平移少量，並共用一次contact event。

**接入契約**：`.omx/jjk-yuta.js:54–75` 已有body/Rika的contact語意；把trail資料交給這個動作clock，不另開setTimeout。前搖與收勢無傷害；一次真正斬擊可有三條光痕，但PercentHealthDamage、吸血與DamageSplash只按策劃列出的primary hit次數執行。里香身體仍走 `drawables` 原生排序，不能為了爪痕把整隻里香畫到AirFields遮住乙骨。

**預算**：桌機36點、手機18點；96步LUT只在新動作／角色尺寸變化時建立；每owner固定24個尾跡槽，壽命140ms；撞擊碎片最多12片，以種子預生成方向。死亡、換世界、owner失控、clearFields都刪除cast資料，暫停直接停clock，不以真實時間推進。

## 7. 建議先後順序與討論問題

1. 先決議卡牌能力表、primary／secondary事件規則、三人的互斥變體；不以更亮特效遮住構築問題。
2. 第一個可交付演算法選刀痕或額砲profile：局部、可驗證、不需要改主畫面快照架構。
3. 天空折射先做單片0.45秒事件；通過DPR／遮擋／分身壓測後才擴展持續幕。
4. 動作與碰撞共用castId、clock、foot-space shape；美術只提供點與語意影格。先禁止多個模組各自重新推導傷害形狀。
5. 每次加新流派，至少自然開局到第一首領、20級既有卡牌build、低階手機模式三組檢驗；20級開局本身不證明升級體驗。

交叉討論時希望其他三位回答：是否同意本次不加新按鍵而以互斥變體提供選擇？數量無效卡要動態隱藏還是每角色新增映射？擴散要保留每鄰居語意還是採總額預算？第一個boss前的成形時間目標是多久、用哪種真實自然成長證據驗證？
