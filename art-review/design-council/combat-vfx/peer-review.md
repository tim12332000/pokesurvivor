# 第二輪互評紀錄：程式特效 Agent

第一稿 `proposal.md` 保留原樣。這份文件記錄實際發出的問題與收到的回覆摘要；沒有把推測寫成同儕已答覆。未修改正式遊戲程式。

## 我提出的三個問題，以及實際回覆

### V1 → 遊戲企劃

**我問**：Lv5新增互斥專精卡會多吃一次三選一機會，為何不先做3／5階功能分歧？同cast外圍擴散應排除primary集、每target一次並取最高原始直接傷，避免遍歷順序；數量資格需要查實際受益者。

**企劃實際回覆**：接受P0先修卡效用，把第一稿Lv5獨立新卡型改為後備。先測功能階級＋19卡預算；若仍同質，再測主招三階同一升階機會的形態二選一。接受擴散primary排除與max傷害；指出我把卡片自身分身當成可增員的數量消費者是錯誤。

**我的修正／反駁**：實讀 `self-clone.js:124–158` 後承認例子錯誤：鏡像Quantity旗標不等於使用；卡片分身固定每卡一人。只有它複製的技能本身讀取數量（例如石流散射）才有間接受益。接受先功能階級，保留長局收斂疑慮，不宣稱兩種投資順序已是成熟流派。

### V2 → 動漫／美術

**我問**：「同一CastEvent契約」不能誤成全局只有一個body clock；里香與身體並行、反射在resolve前。提議分body／companion／reaction channel，由各現有模組發布同型事件而非立刻重寫整套引擎。詢問最低可讀折面與不可被扭曲的資訊。

**美術實際回覆**：接受channel細化；同一契約是結構一致，不是所有演員共用同一時鐘。最低折面為主折線、兩側明暗面、與接觸同步的裂開／回復；拒絕主canvas連人帶HUD回授扭曲／高頻白閃。特別要求capture與composite都在液體後、Hazards之前，不能只確保截圖沒危險卻在後面蓋住危險。

**我的修正**：接受，將層序精確改為背景專用hook，保護玩家、里香、敵人、阻擋props、彈道、命中輪廓、危險預告和HUD。原型仍是獨立背景畫布，沒有聲稱已接正式圖層。

### V3 → 玩家體驗／平衡

**我問**：四招全滿後功能rank路線可能收斂；如何證明不同投資順序是有效分流？全畫面2快照／96頂點／24碎片應用哪種壓測矩陣確認，不能用三個空場平均值定手機預算。

**平衡實際回覆**：接受長局收斂批評。先看第一首領前與固定19卡預算，含通用卡、不強迫全技滿；5種子×四考題仍同質／一路全勝才引入互斥變體原型。預算僅是待測假說。矩陣至少64移動怪、fan/ranged/beamer、0／2／6卡片分身、Quantity0／1／上限、CD0／上限、擴散0／高、DPR1／2、相機移動、手機／實機與雙端。

**我的修正**：採用這個矩陣，不以直接cap分身2人迴避壓測，也不將裝飾LOD當成傷害LOD。互斥變體只保留後備，不先增加操作或卡型。

## 三位同儕對我提出的問題，以及我的實際答覆

### G1：擴散總額與錯誤分身例子

企劃指出：我提的max外圍傷仍可能隨外圍人數增加總量；總額分攤會暗削既有單體擴散卡。要求保留per-neighbor語意、只除去同AOE互濺與次序問題，並更正Quantity例子。

我答覆接受：MVP保留每外圍10%語意，明示總量仍隨外圍m增加；總額分攤列候選B，沒有共識不得放入P0。裝飾上限不能截斷傷害。新增獨立純函數測試證明去重／遍歷次序／consumer判斷；並向企劃確認卡片分身不因Quantity增員。

### A2：全畫面預算、記憶體與資訊保護

美術實際開啟原型，指出每owner快照乘上分身會倍增；每三幀刷新也不能用一次snapshot的成本宣稱。詢問全局上限與最低降階。

我答覆：桌機全畫面2張512²、手機1張256²；應用層RGBA分別2MiB／0.25MiB，不是瀏覽器／GPU總記憶體上限。桌機48貼圖三角、手機12貼圖三角，總96頂點／24碎片是初測假說；本體正在接觸的cast優先，分身以距離／castId穩定排序。超額保留一主折線和兩個明暗面。第一版單次快照≤0.45秒，不先刷新2.3秒持續幕。美術回覆接受這份精確化。

### B2：低階可讀性、接觸pulse與CPU複雜度

平衡要求global預算與敵方危險優先，並指出「每cast只一次」會吃掉里香第二次合法接觸；飛行彈的未來primary不可預知。也要求用現有 `DamageSplash.hit` 輸入的 `primaryDirectDamage`，不能偷改成HP實際損失或盾後數字。

我答覆接受：去重鍵改為 `(runEpoch,owner,castId,contactPulseIndex,target)`。石流同輪射線是一個pulse；里香0.22／0.48秒是兩個pulse；飛行彈每個原生impact獨立，不延遲／回滾。max使用攻擊／屬性／天氣／暴擊後的primaryDirectDamage，排除percent附傷及secondary。傷害事件數可從交叉多次變成每外圍一次，但朴素查鄰居CPU仍最差O(P×M)，不能聲稱程式已線性。企劃與平衡都確認這份精確化。
