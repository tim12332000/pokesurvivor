# 四人共同遊戲設計：構築、戰鬥事件與程序特效

**後續進度：使用者已授權實作，主要規則與特效已接入正式入口，見[實作首版](runtime-release.md)。** 下文保留當時設計定案；未完成的長局／真人／實機驗收仍明確區分。

狀態：四份獨立方案、第二輪直接交叉討論及第三輪四方複核完成；各方要求的精確文字修訂已納入。這是下一版設計與獨立技術原型；以下新玩法尚未接入遊戲，也未宣稱已完成整局平衡。

## 1. 設計基礎與不可混淆的現況

本方案沿用目前PokéSurvivor跨界遊戲，涵蓋共用成長、獎勵、敵人與操作；用乙骨、石流、烏鷺驗證角色差異，同時保留鳴人、手鞠、我愛羅、沛恩、君麻呂等既有角色的有效規則。

| 已查核的事實 | 設計約束 |
| --- | --- |
| 個人版正常開局已強制永久能力全滿，包含攻擊倍率1.4、CD倍率0.76；預設遊戲倍速2 | 不用零強化的新手數值作正常基準，不混算牆鐘與遊戲秒，不重啟農金幣買能力。 |
| 基底有主動槽，但JJK三人全部slotless自動施放；其他角色有不同覆寫 | 按有效能力設計，不把基底註解當所有角色現況，不強迫既有角色改操作。 |
| 角色level、學會招式、招式rank、通用卡是不同進度 | 到Lv3只是可學，不是自動學會；20級不等於四招五階。 |
| 20級試玩只設level並解鎖四招一階，未配置19次選卡 | 試招、標準配裝、自然成長分開標示及測試。 |

| 同pulse的AOE逐敵觸發擴散會有主命中者互濺問題 | 去重須保留合法多段接觸；不能用整招一次去重吞掉里香第二擊。 |
| 羈絆依主動群組可融合性；缺口不只JJK | 獎勵依能力與合法轉移判斷，不能新增JJK限定補丁。 |

程式與實玩依據：[企劃機制證據](gameplay/mechanics-evidence.md)、[玩家／平衡第一稿](player-balance/proposal.md)、[程式特效第一稿](combat-vfx/proposal.md)。各短局是原生按鍵／選卡輔助觀察，不是公平角色排名、真人手感或完整首領測試。

## 2. 核心體驗與整局循環

玩家觀察威脅與地形，藉移動排列敵群／取回XP，在三選一時決定本局投資，再以敵潮、支援群與首領驗證取捨。死亡或退出後，結算要能解釋失敗原因和主要構築。

保留單搖桿／WASD、自動索敵、三選一、現有寶箱與裂縫風險。既有主動槽角色保留切換；本次不增加四個強制手動技能鍵、第二搖桿、新能量條或新貨幣。這是控制複雜度的決定，不把「自動」當成可以沒有構築與走位選擇。

保留180／360／540／720／900遊戲秒的首領基線。900秒是第五既定主線首領生成時刻；結算／繼續節點須等該首領被擊敗，以主線首領槽位識別，不用時間到達或混入裂縫的 `pl.bosses>=5` 判斷。節點只明示既有結算／繼續入口，選繼續後本局不反覆彈出，不新增勝利判定、加成或移除無盡玩法；30分鐘審判仍保留。敵包配額、XP曲線及首領難度須另用樣本比較，不在本輪先改。

## 3. 成長：先驗證功能升階，保留真正分歧的完成條件

第一個比較版本沿用學招與五階升級，在三階加入用途變化、五階深化；佔原本一次選卡，不免費加能力，不新增路線彈窗。1／3／6／9僅暫作現況基準，是否調整取決於自然成形時間。

六條候選路線的目標如下，都是遊戲設計，不冒稱原作技能樹或已實作功能：

| 角色／方向 | 功能升階的候選行為 | 玩家行為與機會成本 |
| --- | --- | --- |
| 乙骨・近身接力 | 刀命中建立單一短標記，里香下一次合法協擊優先同目標；後續改善近身覆蓋 | 進刀距、擊後抽離；優先刀／咒言／生存，較少投資里香與顯現。標記不免費多跳傷害。 |
| 乙骨・里香窗口 | 投資接近可靠度、固定落點範圍及顯現窗口；每個owner同時最多一個里香演員，本體與卡片自身分身可有各自owner，畫面須可辨來源 | 以走位把群體引入落點，承擔往返／爆發空窗；刀術投資較低。 |
| 石流・直線精準 | 集中主要目標與穿線收益，保持鎖向、可讀前搖及側後缺口 | 排線、維持距離、對精英；不兼得全向追蹤、超寬、無前搖。 |
| 石流・散射清線 | 投資扇面／道數與小群爆心覆蓋；同敵每pulse仍一次 | 繞群取角度，花卡在數量／散射而非集中對王；cap與取整須顯示。 |
| 烏鷺・碎面控場 | 投資扇面覆蓋、固定區域與短弱減速，保留首領抗性 | 中距引群、換路；反射幕較低投資，近身仍危險。 |
| 烏鷺・有限反擊 | 已學幕後，只有真實敵彈攔截才授予同幕一次的反擊條件紅利 | 辨認射界與幕空窗；沒有敵彈不白送AOE，也不先強改正常敵包保證有彈。 |

**軟分流不是完成保證。** 每角色在10／19／35次相同選卡預算下，比較A、B、均衡配裝，測近身圍攻、遠程、支援群、單體首領四情境。記錄站位／距離、優先目標、承傷、XP回收、施放與排隊、擊殺／TTK。每路線需有可辨行為和至少一優一劣的情境，不能只換顏色或改總DPS。

若19／35卡路線收斂，或均衡在所有情境都不劣，必須進入互斥形態比較版本：已學核心技由二階升三階的同一次既有up機會，提供A／B兩種形態；選一張同時完成升階與分歧，只消耗一次正常選卡，不是先升三階再免費選或額外收專精卡。本局不能兼得、跨局重選。不採Lv5向未學天空幕玩家硬發反制牌，不新增免費卡或強迫彈窗。觸發門檻與數值仍須測試，不把較省工的軟分流直接宣稱成功。

## 4. 卡牌、試玩與獎勵契約

### 卡池按真正受益能力判斷

每個已學技能／生成器宣告支援的成長軸與上限，卡牌透過同一套受益查詢產生資格及選後預覽。不要只靠角色dex、卡名、存在分身或圖示推論效果。

- 數量MVP採共用×1.25乘算，最後取整；石流散射保留9道cap和同敵每pulse一次。這是有強度影響的修訂，需和現有線性版本對照，不當成純改字。
- 無實際count consumer或全部達cap時不出數量卡。SelfClone每卡一隻；繼承Q只在被複製技能真有consumer時有用。乙骨／烏鷺只有SelfClone仍不使數量有效。
- 「3→3、累積未跨整數門檻」與「永遠沒有有效對象」不同。前者可保留，但顯示累積門檻及後續數值；後者應排除。
- CD預覽顯示名目倒數及「就緒待出手」狀態，測量實際施放間隔。功能升階不無條件刪除可辨前搖。
- 目前沒有通用範圍卡的有效證據。若另加，索敵距離、命中長／寬、控制半徑、裝飾外框須分開，不把倍化誤稱全技能範圍成長。
- 軍糧丸等立即收益卡須檢查當前有效性；滿血無其他收益時不出。各種附傷／吸血／分身都要有獨立的收益及事件測試。
- 首次特色卡沿用可跳過的機會；同屏保留至少一個非特色生存／通用選項。多項特色機會衝突須排程或合併，不把三格全塞guaranteed。

### 三種20級狀態分開

1. 現有試招：20級、四招一階、零次配裝選卡，明確標籤。
2. 標準配裝：從正常基礎生成19次合法投資，包含學三招的成本；保存每一步level／cardKey／受益快照。不能先免費學三招後再多送19卡。
3. 自然養成：記錄真正的offers、選擇、重抽、XP及寶箱來源。只有這類資料可支持自然成形時間；固定配裝不冒稱自然隨機抽到。

### 羈絆按能力分流

原生審計已確認：完整合法學招後，鳴人、沛恩、君麻呂、乙骨等可能沒有可融合選項；手鞠、我愛羅則可融合。規則須看有效啟動結構及可達的未來狀態，不能只看當下slots為0或某段角色ID。

- 目前有合法bondOptions：保留原融合。
- 暫未學足、之後確有合法融合能力：可暫存並清楚解釋所缺條件，不浪費token或卡住遊戲。
- 結構上不可融合：提供共用的有效精通／成長獎勵轉換，依已學能力及收益資格決定；不捏造領域、不另造貨幣。

轉換收益、滿階後退路及與既有融合價值的比較屬後續可玩驗證；不在設計稿假稱已平衡。原有購買／存檔資料保留，不因個人版全滿基礎而抹除。

## 5. 傷害與多演員事件：先定契約再寫新效果

每個actor/channel使用同型事件，但不共用唯一身體時鐘。乙骨body與里香companion可並行；反射reaction保留原resolve順序。

```js
// 擬議契約；不是目前遊戲已存在的API。
CastEvent = {
  runEpoch, ownerId, actorKind, channel, castId, moveId, seed,
  sourceWorld, aim, shapeSnapshot, emitterAnchor,
  windupStart, contactTimes, recoveryEnd,
  cooldownStartPolicy
};
ContactPulse = {
  runEpoch, ownerId, castId, contactPulseIndex,
  primaryHits: [{ targetId, primaryDirectDamage }]
};
```

`runEpoch`由startRun建立新nonce／Symbol，不能使用穩定的`G.Game.st`統計物件當局次身分。暫停停模擬時鐘；死亡、換世界、換局及失控清理事件。外觀訂閱事件，不自行用setTimeout或真實時間決定傷害。

### 擴散MVP共同規則

1. 每個真實接觸pulse先收集完整primary集合並去重，再執行直接命中。石流同輪多ray共用pulse；里香0.22／0.48兩次重擊是不同pulse。
2. 同pulse primary不互相擴散；外圍每target只受一次，取相鄰合法primary的最大 `primaryDirectDamage` ×擴散率，避免迭代順序影響。此欄即企劃所稱 `outgoingDirectDamage`、現有 `DamageSplash.hit` 的出手輸入：在技能／角色攻擊／屬性／天氣／暴擊等直接倍率確定後、primary護盾吸收／overkill／實扣HP截斷前保存，排除生命剝奪附傷與secondary。外圍仍走原生護盾／hurt，不重算屬性／天氣／暴擊；各模組不能混用實扣HP或帶附傷總額。
3. 保留單體對每個外圍鄰居10%起的現行語意，不偷偷改成10%總額分攤。總額分攤另列為B方案／可能削弱，須改文案及做比較。
4. 分離飛彈逐次撞擊立即各成pulse，不預測未來primary、不回滾已發生傷害。所有次生傷害仍不觸發吸血、控制、百分比附傷或遞迴擴散。
5. 合法傷害事件使用原生歸屬與記帳，特效線條、爪痕、碎片不增加hit數。分身的owner、傷害／附傷繼承只計一次；裝飾總預算不合併掉合法多演員傷害。

去重可限制實際傷害事件數，**不保證CPU線性**。朴素鄰居查詢／最大值仍可能是P×M，加上遮擋路徑成本；需利用現有空間查詢並在64怪、分身、滿數量／附傷下量測。

乙骨顯現的待測節奏修訂為6秒有效期＋結束後恢復段，CD卡只縮恢復段；12秒基礎恢復僅初測假說，須檢驗最高CDR仍有空窗及整體強度變動。這不是純特效修正。

### 全畫面預算及最低品質

原先每owner快照、每3幀更新的提案已撤回。第一版只取一次局部背景，事件≤0.45秒；2.3秒持續動態折射另做整合測試。

- 桌機：全畫面最多2張512²快照；手機最多1張256²。RGBA應用buffer約2MiB／0.25MiB，不冒稱包含瀏覽器／GPU所有複製。
- 背景折面全畫面最多桌機48／手機12貼圖三角片，網格共享頂點上限96；24片裝飾碎片另作全畫面預算。光束／刀痕另遵守輪廓點與可見事件數預算，96不是整個遊戲所有幾何的總cap；不能把per-owner數字乘上所有分身。
- 主角當下接觸優先，再依鏡頭距離與穩定castId排序。超預算降裝飾，不改真實碰撞、contact時刻、敵方危險或主要方向提示。
- 天空最低品質仍保留一主折線＋兩個明暗面及正確裂開／回復，不退成泛用圓圈。
- 分身可低飽和／細輪廓區分owner，但不縮小真實範圍暗示。兩隻分身只作壓測點，不在未測前硬設玩法cap。

原型已測Node幾何／接觸斷言、實際Chrome三模式、時間拖曳、暫停、高低畫質、DPR及手機版面。300次靜態draw平均只代表本機單原型成本；正式整合仍須計snapshot捕捉、主遊戲、分身、危險、HUD及真實手機p95／p99。

## 7. 美術、動漫與介面

原畫負責人物身份、肢體動作、里香甲殼／長顎；演算法負責光束輪廓、短拖尾、折面紋理及有限碎片。兩者共用錨點、shape與接觸時刻，不能用變形替代缺少的角色動作。

保持仙台時期造型與能力語意，使用「宇守羅彈」已查核名稱；四種砲擊副標、360度幕、卡牌數值與功能升階明列改編。不補未證實領域、復活女孩靈魂或無限免傷。

烏鷺較高遮覆的不透明天空覆片服裝為本遊戲改編，不宣稱動畫原衣裝；保留長浮髮、金耳飾、裸足與天空當面的辨識。

介面增加的資訊服務當下決策：

- 選卡：本次有效對象、當前→選後、上限／累積進度、行為代價。
- 戰鬥：冷卻／就緒待出手／施放中；顯現有效期與恢復分開。
- 結算：主要承傷來源、直接／次生／反射／分身貢獻、實際施放及排隊，幫玩家修正下一局。
- 手機：玩家頭身腳及敵方危險可辨，己方裝飾不可蓋過核心資訊。
