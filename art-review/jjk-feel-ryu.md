# 石流：讓命中蓄能準時兌現

2026-11-05。本輪依更新後[企劃 Agent 指引](design-council/gameplay/agent-instructions.md)檢查目前實作，沒有修改已調好的火影角色。此頁區分本次受控量測、程式變更與尚未證明的主觀體感。

## 查到的問題

普通砲每次施術真正命中後蓄一格，三格封頂；全力砲取代下一次排定的普通砲，並保留自身冷卻。原 11 秒冷卻讓「已打中三次」和「得到大砲」分離：60 秒情境內，玩家約 17.8–21.3 秒已滿蓄能卻仍在等全力砲自己的冷卻。期間又有 8–14 次普通砲在滿三格下施放，無法再提供蓄能。這是可觀察的回饋延遲，不是測試通過與否或單看傷害可以辨認的問題。

身體排隊、下一次普通砲時機與全力砲冷卻的等待可能重疊，不能把表中秒數相加當作完全無攻擊時間。原恢復段在每局僅累計約 3.6–5.3 秒，並非這次優先縮短的對象。

## 本次變更

`.omx/jjk-ryu.js` 的全力砲基礎 CD 由 11 改為 **5.4 秒**，等於三次 1.8 秒普通砲週期；技能登記與玩家說明由共同整合同步。仍需要三次真正普通砲命中，再等下一次普通砲機會才替換出招。普通砲空射不蓄能，同一砲打到多人只蓄一格；全力砲起手消耗三格，保留 0.75 秒鎖向準備與 0.7 秒釋放恢復。

傷害、判定寬度、射程、鎖定方向、散射飛行與固定爆點均未因這項節奏修改調整。較密集的全力砲確實會改變整體輸出與其他招式排隊，屬玩法調整；不是純美術修正。

## 同成本前後量測

工具：[profile_ryu_feel.py](../tools/profile_ryu_feel.py)。每個案例 60 秒模擬，以正常入口載入，僅由原生自動戰鬥排程出招，不手動呼叫技能。每次新建瀏覽器 context，固定無暴擊與相同的確定性位置軌跡，沒有隨機生成的敵人配置。

- 一階配裝：合法花費 11 張卡，其中三張學招、八張攻擊／冷卻屬性。
- 三階配裝：合法花費 11 張卡，其中三張學招、八張技能升階，四招各三階。
- 另各加一張合法自身分身卡重跑，兩種配裝的分身比較皆為 12 張成本；分身由原生更新移動、自動施術並獨立累積命中／蓄能。
- 靜止單靶、橫向移動首領、八方向移動敵群，共 12 個案例。移動首領的橫向最高速度 144 單位／秒；玩家也按固定軌跡移動。這是控制變因的接觸與節奏研究，並非真實鍵盤／觸控操作或自然敵方 AI 長局。

以下為玩家本體，數字為「修改前 → 修改後」。全力砲命中施術數以**已結算施術**為分母，避免把第 60 秒仍在準備中的砲算成空砲。

| 同成本配裝／情境 | 全力砲施放次數 | 全力砲命中／已結算 | 已三格卻等自身 CD | 三格封頂後又放普通砲 |
| --- | --- | --- | --- | --- |
| 一階／靜止 | 8 → 12 | 7/7 → 12/12 | 18.55 → 0 秒 | 14 → 0 |
| 一階／移動首領 | 8 → 10 | 3/8 → 8/10 | 18.73 → 0 秒 | 13 → 0 |
| 一階／移動群體 | 8 → 11 | 7/8 → 11/11 | 17.78 → 0 秒 | 12 → 0 |
| 三階／靜止 | 5 → 8 | 5/5 → 8/8 | 21.33 → 0 秒 | 11 → 0 |
| 三階／移動首領 | 5 → 7 | 1/5 → 1/7 | 19.93 → 0 秒 | 8 → 0 |
| 三階／移動群體 | 5 → 8 | 3/5 → 7/8 | 20.53 → 0 秒 | 11 → 0 |

加入一個原生自身分身的六個案例，同樣保留本體獨立節奏；分身本身也確實施放、命中，沒有借本體事件冒充分身輸出。完整分身紀錄、原始事件、命中時間與兩端 Ryu 程式雜湊見 `.omx/state/jjk-feel/ryu-baseline/cadence.json` 和 `.omx/state/jjk-feel/ryu-final/cadence.json`。

這批證據支持「三次命中後不再被第二層長冷卻攔住」。它**不支持**「所有配裝打移動首領都變好命中」：三階移動首領仍只有一發真正打中，且前後發射時刻改變會改變橫移目標剛好在哪裡，不能把一階命中提升全歸功於瞄準改善。鎖向 0.75 秒的風險保留，後續應觀察玩家是否能看懂並用走位安排砲線；不直接加追蹤、擴判定或傷害補償。

## 當次驗證與界線

`tools/test_ryu_identity.py` 桌機、手機各 20 項通過，證據 `.omx/state/jjk-feel/ryu-identity/report.json`。包含三次真命中蓄能、下一次普通砲替換、恢復期間可移動、散射先飛行再碰撞、遮擋／單次直擊、固定群聚爆點、暫停與死亡／換世界／新局清理。JS 語法與 Python 編譯檢查通過。

受控模擬沒有測自然生成、選卡壓力、長局存活、手機 GPU／RAF 或玩家主觀爽感；不能據此宣稱角色已全面平衡。應再以正常入口鍵盤／觸控實戰與玩家回饋評估本輪整合。
