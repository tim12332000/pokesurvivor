# 完整新角色 SOP：一次需求，內部迭代，完整交付

適用 PokéSurvivor 完整新增、生成或整體重做跨界角色。使用者只說「新增某角色」也預設走本流程，不必再提醒多 agent、總監、完整動作、成長驗收。單點修圖／已知 bug／單招調整只走相關品質與製作段落；若使用者明確只要設計、原型或素材，依該範圍交付。

「一步到位」是由 agent 承擔完整製作與內部返工，不是保證第一次生成就完美，也不是只做第一版骨架後等使用者指出缺什麼。不得以耗時、固定輪數、技能數、圖數、測試數或自評分數作為完成理由。

## 分工與總監

主代理負責整合、共享合約、檔案所有權、解決依賴及最終交付。完整角色預設使用原生多 agent，另外設獨立品質總監，不能等使用者說太隨便才啟動。遵守工作區並行上限；不要寫死模型型號或遞迴無界派工。工具不支援時如實說明並改採可行的獨立審查，不假稱已啟動團隊。

| 職責 | 必須產出／檢查 | 寫入邊界 |
| --- | --- | --- |
| 企劃 | 起始→少量卡→成形循環、移動選擇、技能接力、真成長消費端 | 短共享合約；不搶寫共用程式 |
| 動漫 | 指定時期的完整能力盤點、確定遺漏／取捨、關鍵動作與形態；獨立看正式畫面 | 來源與動作契約 |
| 美術 | 有效身體／武器動作、材質、形態、方向、圖格與端點；實看遊戲尺寸 | 素材、metadata、繪製runtime、素材產生器 |
| 戰鬥 | 真幾何、接觸事件、仲裁／生命週期、卡牌與預覽 | 專屬模組；共用接點由主代理指定單一作者 |
| 測試 | 真成長／輸入、幾何與取消反例、自然局、完整原生片與包核對 | 驗證工具與證據；不替作者改期望值掩蓋失敗 |
| 品質總監 | 持續讀實際程式、看當次畫面／影片與成長資料，對照既有成品並退回缺口 | 一份精簡看板；不代替美術或動漫驗收，不搶寫產品 |

總監不能只收「完成」訊息或報告存在。看板維持：各 lane 已落地產物、尚缺依賴／問題、退回理由、下一個可驗成果、修正後的獨立重驗。若只見源圖／profile更新，尚無runtime／真命中，就保持未完成；依賴卡住時主代理調整有界所有權，讓可測部分先落檔，不能全隊等一個巨型未落地草稿。作者自查不等於獨立放行；必要的程式審查可在有空出的 lane 接續處理。

## 1. 先查現況與既有品質

讀專案 `art-review/design-council/charter.md`、對應角色指引及[品質準則](character-quality.md)。確認實際載入鏈、ID／存檔、當前覆寫與正常入口；挑與新角色相近的現行成品，實看起手、真接觸、追身／撤退、群攻、卡牌連動及高潮，而非只讀舊交付報告。

動漫先盤點該時期確定能力、現有但不足的轉譯、尚未確認／後期能力與本作改編。完整角色不等於必須收錄所有原作招式，但核心遺漏要有明確取捨，不能未盤點就把現有五招修數字稱作完整。可合理推定的例行選擇自主處理；真正影響身份與範圍的缺失才釐清，不把普通下一步丟回使用者批准。

## 2. 收斂可開工合約，立即分段製作

用一份短合約定：每招用途、來源／方向、起手→釋放／接觸→後果→收勢、真幾何、移動影響、與其他能力的接力，以及起始／第一張或少量卡／成形的可見差異。定共享能力資料、素材socket／phase API、各作者檔案及足夠的完成證據，讓素材與程式並行；不靠大量提案拖延落地。

相異能力必須各有成立的物理或事件語意。若近戰、吐息、刀斬實際仍是同一個瞬時扇形換色／改距離，總監退回設計；程序幾何適合做流動／軌跡，不得以簡單圈線冒充缺失的身體、武器或主要變身形態。

按角色需要分清身體、夥伴、反應與場域時計。必須共用身體的相位要明列；已釋放的效果／獨立演員不應隨意被另一招取消。高數量／短CD時須驗整套循環，不能因一招拖長而永久吞掉普攻或其他核心技能。不要反向強迫每個角色套同樣通道、招數、變身或上限。

## 3. 素材與實際事件一起接

先查現用素材／分派，再補真正缺少的姿勢、形態與方向；新點陣素材依imagegen流程保存提示、輸入、原始輸出、版本與SHA。手、肘、足、嘴、握柄／刀尖、腳底與夥伴位置以當格量測，繪製與模擬共用取樣／transform，不各寫一套近似位置。

- 所有實際可攻擊方向要成立；不能圖向右卻只旋socket去打上方，也不把整個站立人形旋轉來代替方向圖。
- 待機／行走／接觸／收勢、出生／退場及普通／強化要真的播放。不能站姿滑行、全身bob假走，或每段一直停在同一個命令手勢。
- 素材alpha要用像素資料及實際背景合成確認；隱藏RGB不等於可見霧。檢查跨格長武器、裁切、腳底、鏡射、像素密度；倒下／蹲姿不放大成站高。
- 新形態要在正常桌機／手機入口看得到身份與全身關係。構圖裁掉頭／重要形態不能以源圖完整放行；必要調整須限於該角色／窗口，保持實際刀程、移動意圖和其他角色調校。
- 正式圖集、metadata、載入、HUD、圖示、學習列、預覽與打包同步。只包選用runtime素材，巨型原圖與展示片不加入正常開局下載。

## 4. 投資真的改變行為

技能／卡牌／預覽共用真能力資料；每階說明功能與受益端，查第一張、幾張、上限與成形配置。不得顯示沒有被攻擊消費的damage／range或解鎖，取整未變要明示累積，封頂後排除無效卡。

新增數量／升階若影響常駐演員，定義即時差額與下一次施放的界線；不能重設既有個體位置、冷卻或壽命偷送收益。技能、數量、冷卻、巨化、自身分身等實際可選投資須按受影響端驗證，尤其可見肢體變大後不能被固定候選搜尋漏掉。來源／接力不遞迴，空招或不合資格的分身不能假蓄本體高潮。

## 5. 自動化與自然成長是兩個必要面向

依新行為驗真範圍內／外、牆、物件、移動本體／敵人、每段歸屬、同波首靶回呼取消後的第二靶、暫停／死亡／退學／換場／局次／分身。逐sim使用前一個真世界端點，不預掃未來姿勢；繪製只讀。回歸要對應真反例，不寫只重述實作的測試。

另從正常Lv1入口用真鍵盤／觸控、自然敵潮和真正出現的選卡，記錄當次永久能力、種子／策略、每張卡與時間／成本。至少看到本角色的招牌自然成形與完整核心循環；有變身或高潮者，另驗完整窗口及收束，不強迫其他角色新增限時大招。短片仍未學到後期核心就繼續正常局，不固定成「18秒／120秒／8分鐘／46級」模板。沒有改等級、XP、無敵、AI、敵潮或手動推技能clock才可稱自然養成。

死亡／未成形如實記錄，分辨設計、門檻、卡池、操作策略與程式問題，不能補血、加等級或挑成功片冒充。比較固定能力與成本，亂數／遭遇分歧不可當同場DPS結論。受控高配另驗上限、低畫質與多演員可讀性；不能取代自然流程。

## 6. 總監逐關退回，直到完整候選

設計→素材／接線→真機制→自然成形／完整演出→包與線上；每關憑實物，不以作者自評放行。每輪只退回具體不成立的部分，作者修正後獨立重驗；測試全綠而動作、身份、連動、成形證據缺失，仍未完成。使用者否定的舊通過必撤回作完成依據，保留歷史和反例，不能寫成「已通過，只差主觀樂趣」就停止。

美術與動漫各自實看當次正常入口、首段／後段／末段／收勢／消散；原生影片檢實際播放時間、HUD與當段state。設currentTime卻回0、純推Combat但未推原生相機、靜圖拼接、較早版本片段均不能證未看的新版本。聲軌存在不代表聽評。高配交會可短暫遮擋，但主角、敵方威脅與可走路面不能持續消失；先處理具體遮擋，不任意砍合法火力。

足夠證據通過後停止新增機制與無關擴測；後續只有新改動、失敗或未解關鍵問題才重驗。凍結候選再跑長局，記來源manifest／hash；若最後僅文字或格式差異，明示可核對差異與定點驗證，不冒稱片段來源相同，也不無故重拍全局。

## 7. 完整交付與發布

角色在正常選角、學招／成長、實際戰鬥、素材、HUD、生成器與正式包均成立，才交付完整候選。主代理確認總監未解阻擋為空，收相關lint／語法／測試／打包及未驗條件，不能只交設計書或丟「要不要繼續」。

已有涵蓋本任務的有效發布授權，就直接完成Lore提交、推送、部署與公開核對，不再問一次。SOP本身不新增跨任務／跨服務的發布、改權限、換域名或對外發文授權。先查實際遠端部署來源；commit、push、queued都不等於網站已更新。失效時只採授權範圍內可逆方案並記錄，不能繞過保護、假稱成功；確需外部權限才明確說出具體阻礙。

公開入口須真開局，重要程式／metadata／圖集與發布產物對上，文字換行差異與程式差異分清；影片實際可播／seek且與標示來源一致。交付遊玩連結、玩家可感差異、驗證／來源與剩餘限制。不要把瀏覽器手機視窗、受控靶場或未檢視內容誇稱實機長局、自然養成或真人認可。
