# 新增火影角色：素材到遊戲

## 1. 確認角色版本與能力

先確認現行分支、工作目錄、已有角色與使用者指定的角色時期／服裝。沒有指定時從任務與現有角色推斷；只有影響造型或技能的重大分歧才詢問。

查官方角色、動畫／漫畫或官方遊戲資料，列出角色定位、可用招式與有依據的 AOE；記錄直接來源及遊戲改編界線。素材研究從使用者指定的 https://spritedatabase.net/game/55 開始，必要時再查其他原始來源。圖集名稱不能證明所有動作存在：實際檢查原尺寸圖、朝向、待機、走跑、施術、受傷及倒下。

## 2. 訂出同一套風格與動作清單

本版基準為 `art-review/redrawn/` 的現用圖集。參考 Ninja Council 3 的輪廓、比例、像素和動作語意，重新製作角色圖；研究用擷取圖不等於可直接接入的成品。若使用者另行要求採用特定素材，明確記錄來源與署名，仍需檢查一致性。

設計完整新角色時，可安排專門技能設計 subagent 查其他遊戲官方／作者的技能與平衡資料，提出清怪、單體、機動或爆發的分工、學習進程與代價；同時讓素材、戰鬥實作及測試走獨立工作範圍。建議與已完成實作要分開記錄，避免設計文件把尚未做的連動寫成現有功能。小李的四招及來源對照見 `art-review/lee-skill-design.md`。

- 按角色列出普通形態、需要的變身、共通動作與每招的準備／出手／命中／收勢。分身或其他獨立演員也要列入。
- 普通角色依實際玩法安排正面、背面、側面；鏡射與側面替代上下方向必須明示，不能宣稱獨立八方向。
- 設定共同身高、頭身比、描邊粗細、像素密度與主色。用同一角色圖作後續生成參考，避免不同圖集各自變成另一種畫風。
- 變身要有自己的待機、移動、攻擊與受傷；已畫在圖裡的外衣、尾巴或手部能量，不再疊畫第二份。

## 3. 製作並登記素材

使用 `imagegen` 製作／修改點陣圖，要求透明背景、固定身體比例、足夠影格間距及可辨識的動作。新增版本檔名，原始輸出不覆寫；將選用輸出放入專案，保存提示詞、參考角色圖與 SHA256。參照 `art-review/redrawn/provenance.json`，不要把生成圖標成官方擷取素材。

原圖看起來有色底時先檢查 alpha，並合成到草地／棋盤底查看；不要只根據透明 PNG 的 RGB 預覽判斷。生成格線不一定等寬或對齊，裁切要依實際透明輪廓與已檢視的影格邊界。不要用霧光或大特效的邊界計算人物身高。

每格記錄 `rect` 與腳底 `anchor`，同圖集使用固定的身體比例；蹲伏與倒下會自然變矮，不可把每格縮放成同一高度。比較人物頭部、站姿與施術間的比例；不吻合就修圖，不能只靠改縮放掩蓋頭身差異。

現有登記工具是 `tools/build_redrawn_atlases.py`，輸出：

- `art-review/animation-assets.json`：正常角色與技能繪製使用的來源、影格、鏡射和身高。
- `art-review/redrawn/atlas-map.json`：實體影格登記，亦供審稿播放器精確裁切。
- `art-review/kyuubi-frames.json`：目前僅供鳴人一尾；新變身應按自身狀態接入，不套用鳴人身分判斷。

**工具目前登記鳴人／佐助／小李，並非通用匯入器。** 新角色需要擴充輸入與影格對應；不要把新 PNG 丟進資料夾就宣稱完成。

## 4. 接入角色、技能與動畫

| 接點 | 新角色需確認的內容 |
| --- | --- |
| `.omx/naruto.js` | roster、DEX、選角、角色可用清單；既有 DEX 由 roster 順序產生，避免重排造成存檔角色 ID 改變。已有角色先查其既有 ID，不能重複新增。 |
| `.omx/naruto-skills.js` | 角色主招、額外技能池、角色專屬限制、來源及圖鑑說明。 |
| `.omx/naruto-training.js` | 學習等級、保證出現的招式選項、滿槽替換及綁定；不可把高階招式當隨機起始技能。 |
| `art-review/animation-runtime.js` | `heroes` 的角色 ID／圖集對應、待機／走跑／受傷／倒下、各招準備與收勢、分身；目前只登記鳴人／佐助／小李，新增角色必須擴充，不能讓新角色誤套別人的圖。 |
| 技能專屬狀態 | 手／嘴發射點、持有武器到飛行武器的銜接、場景／死亡清理；原圖已有能量時避免重複效果。保留既有傷害與冷卻，除非任務要求調整。 |
| `.omx/redrawn-init.js`、`js/main.js` | 正常入口等素材完成後才開遊戲；`animationLab=1` 的審稿父頁仍只安裝一次，不把審稿工具列搬到一般遊戲。 |
| `.omx/make_digimon.py` | 重建 HTML 後仍保留正確腳本順序與角色資料。 |
| `tools/build_digimon_site.py` | 明確列入新增圖集及必要資料；目前為七張圖集的明確名單，需依實際新名單更新，不可刪除檢查來略過漏包。 |

審稿頁 `manifest.json` 也要更新，使用實際裁切座標播放。退回／舊版提案可存檔，但不要繼續當作現用素材展示。

## 5. 實玩驗證與交付

先確認測試服務真的來自目前 worktree。現有瀏覽器工具多預設 `8318`；另一個 worktree 若佔用該埠，應調整測試目的地並記錄，不可誤測到舊分支。本機可用 `python tools/serve_animation_lab.py --port 8004` 啟動目前 worktree，正常入口為 `/.omx/digimon.html?lang=zh-TW`。

按變更選用現有工具並加入新角色案例，既有數量斷言要依實際新增清單更新：

```text
python tools/test_animation_assets.py --browser
python tools/test_kyuubi_frames.py              # 只在修改一尾時需要
python tools/test_redrawn_heroes.py
python tools/test_animation_complete.py
python tools/test_sandbox_redrawn.py
python tools/test_rock_lee.py                 # 小李體術、學習進程、原生跳躍與手機操作
python tools/build_digimon_site.py
```

這些工具仍含現有三個角色與招式的固定案例；新增角色必須增加對應驗收，而不是只通過舊角色測試。只檢查程式變數或總傷害不足以證明新動畫已套用。

舊的原始擷取圖裁切檢查可明確使用 `originalArt=1` 對照，但新角色／新素材驗收必須用正常預設入口；不能因為瀏覽器是 headless 就跳過新繪圖層。

必要證據：

- 正常入口能選到新角色；選角／選單頭像、玩家本體與獨立分身皆使用預期新圖，沒有回退舊畫風。
- 真實鍵盤／觸控移動、自動索敵施術、切招、升級選卡、受傷與倒下。檢查手機畫面沒有溢出或遮住主要操作。
- 每招按實際出手時機檢查手／嘴座標、武器持有和釋放、命中與收勢；AOE 用至少三個範圍內敵人及一個範圍外敵人驗證。
- 變身、暫時效果與延遲招式在到期、死亡、切換角色、場景清除及重新開局時正確清理；暫停不推進動畫。
- 浮空與位移要和敵人的真實更新順序一起驗證。技能視覺高度獨立於原生跳躍，加入 `startJump`／`updateJump` 和技能更新交錯、取消的案例；只手動推進技能會漏掉高度覆寫問題。
- 同尺寸的圖集與遊戲截圖比較比例、描邊、腳底和遮擋；桌機／手機比較相同圖格及渲染路徑，不對不同時間相位硬比像素。
- 追蹤實際 `drawImage` 來源及檔案雜湊，確認是此次選用圖集；打包後圖集與腳本齊全，審稿 UI 未混進正常入口。

交付時提供已驗證的本機網址、現用圖集／來源紀錄、測試結果及缺少的方向／動作。沿用使用者本次已授權的範圍；沒有授權時不自行推送、合併或發布。
