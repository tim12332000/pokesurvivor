# 新角色品質準則：把成長做成玩家看得到的力量

石流巨砲、乙骨雙人協戰、烏鷺連續裂面迭代後，使用者認可較誇張的成長方向。本頁記錄可移轉的判斷，不把當次輪數、半徑、技能數或學習等級變成新角色模板。文中程式與設計路徑以目前專案根目錄為準。

## 先確定角色體驗

玩家感受是設計門檻。每招先寫觸發前威脅、當下可見辨識、真實局面改變、可利用的下一步及少量成長差異；以同一遭遇移除此招做對照，若看不出改變就重新設計。控制效果明列是否阻止移動、攻擊、施法、接觸傷害與在途敵彈，名稱與說明不得超過實際效果。受控靜靶、命中測試及視覺分數不證明好玩；使用者已回報無感的項目不得沿用舊「通過」結論。

指定動畫角色時，由動漫 agent 先盤點該時期已演出的能力與遊戲對照，分清確定遺漏、現有但轉譯不足、本作改編、後期／未確認能力，再定完整技能循環，不能只在現有招式清單內修數字。例：「別動」只停止位移而不阻止攻擊時，不能用震懾一詞假定已處理敵方威脅。

先讀當前載入鏈、戰鬥模組與實際畫面，再看歷史企劃。以使用者調好的現行火影角色理解普攻空檔、接觸追擊、群攻規模、卡牌連動和變身高潮；不要把舊說明或舊通過紀錄當成現況。

完整新角色先交代一條招牌循環：如何進入戰鬥、移動改變什麼、技能如何接力、成形後如何壓制敵潮。列出起始、第一張／少量成長卡、成形三階段的可觀察差異。力量幻想可以大幅提高真實覆蓋、接觸次數、協戰與頻率；修命中、縮CD或加裝飾不能單獨代表爽感完成。

技能數與學習等級依角色決定。有用的新被動應接進已有循環，不湊固定四招／五招，也不塞身份無關的招式。原作定義力量來源與動作語意，本作決定數值、卡牌和自動觸發；不借未核對的他人／後期能力，也不以考據為由強制保留舊弱點。

## 把投資變成真實行為

- 卡牌先找真正受益端，再提供選項。檢查第一張、幾張與上限；取整造成當張未變時顯示累積門檻，不假裝已增加攻擊。成形後避免完全無效的數量卡。
- 戰鬥、卡牌預覽、升階和說明使用同一份能力資料。角色等級、已學招式、技能階數和實際選卡成本分開；高等級試招不代表自然養成或合法配裝。
- 每輪真攻擊有獨立接觸索引與歸屬。同輪不重複直擊，合法下一輪可再打同敵；雙人兩來源／兩筆傷害不可去重成一筆。
- 身體、夥伴、場域與反應明確仲裁。有一位夥伴的角色維持同一實體的連續位置與形態，不用假分身湊規模。反擊由真攔截觸發，衍生攻擊不遞迴產生自己。

## 大演出仍對得上命中

角色身份包含造型與能力如何共同成立。烏鷺使用天空／空間折移遮蔽身體重點，不能改成普通服裝或以幾何線冒充；所有動作、鏡射與低畫質保持非露骨遮蔽，臉、髮、四肢和施術動作仍可辨。動漫與美術 agent 必須實看當次正常入口，不以資料盤點替代造型驗收。

此遮蔽應表達視線被空間扭曲而偏折，呈現折移的環境／天空；不是在身上貼固定藍色布片。以換背景、移動與各姿勢驗證材質會呼應環境且持續遮妥。

烏鷺v7的胸腹大片隱去已被使用者否定；腹部正常可見、胸／腰胯遮蔽分離是後續必要條件，不可再以範圍限制或自評通過代替。

用正常尺寸比較普攻／大招、普通／變身，以及首擊、後續段與真正收勢。巨砲有當輪砲口，雙人連打有兩個起點，抓面要拉緊後裂開。先查現用圖格、分派、錨點、時鐘和排程，再決定缺圖或重畫。

移動中的出手源點可跟隨本體；已結算命中痕和固定場域保持當次位置。逐波跟身招式同時驗證下一波活原點與上一波凍結標記。多段動畫依該段局部時間重播，不把下一段前搖截圖標成末段收勢。

低畫質、多演員與高數量可以減紋理／碎片，仍保留真實攻擊寬度、方向與合法段數。繪製只讀狀態，裝飾預算不能裁掉傷害；不以長時間滿屏白光代替力量，玩家、敵彈與移動路線仍需辨識。

新技能同步圖示、HUD真進度、選角學習列和說明。360／390等小尺寸要看計算後的可見性、實際邊界與文字，不能只確認DOM存在。

## 驗證會改變判斷的地方

1. 真正學招／升階／選卡驗證成長，受控高配另測上限。AOE至少三個分散有效目標加一個範圍外目標；檢查牆後、移動本體／敵人、各段HP與歸屬。
2. 暫停、死亡、退學／取消、換世界／局次與分身隔離。傷害回呼也會清場：至少兩個有效目標，第一個的hurt／onDealt取消後，同波第二目標與未來波次都不得補打；單靶測不到這個漏洞。
3. 控制與增益依角色契約驗證，不覆蓋外部減速／原生跳躍，屬性只同步差額，移動迴圈有容差和步數上限。不為每次傷害附送未設計的持續擊退或永久控制。
4. 正常入口、原生自動戰鬥與鍵盤／觸控必驗。變身／多段角色提供包含末段的原生短片；標示等級／技能階數／卡數與受控靶場。靜圖合成不叫實錄，含音軌不叫已聽評音色。
5. 美術／動漫獨立看實際相位及影片採樣，核對來源、身份與遮擋。分數只評具體視覺目標，不能替代玩家認可；實看與未驗的長局／實機條件分開說明。

## 分工、收尾與發布

企劃負責整體循環與成長；動漫負責身份、動作鏈和改編界線；美術把真實幾何與段落畫出來；戰鬥作者負責事件與清理。主代理定共享profile、檔案所有權和完成條件。多agent用在獨立有界工作，不讓所有人同時改共同入口。

先定足夠的交付證據，凍結改動後跑相關檢查。通過後只有新改動、失敗或未解風險才重跑／擴測；同一合約的相容入口不是多份獨立證據。避免收尾時不斷加新機制，簡短報告狀態。

完成涵蓋正常入口、技能池、素材、HUD、生成器與打包。已有有效發布授權就完成提交／推送及公開版本、關鍵資產核對；本準則不替未來任務新增發布授權。Windows／CI換行差異與程式差異分開，以提交內容與實際建置輸出核對公開資產。
